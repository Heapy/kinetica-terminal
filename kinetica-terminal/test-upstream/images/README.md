# Graphics image decoder fixtures

`test/generated/TerminalGraphicsImageFixtures.kt` is generated by
`scripts/generate-terminal-image-fixtures.py`. No expected pixels come from Kinetica.

- 120 PNG fixtures cover every standard color/depth combination, all five filters,
  non-interlaced/Adam7 images, palette and color-key transparency, partial palette
  alpha, one-pixel/narrow dimensions, unknown ancillary chunks and fragmented IDAT.
  The test-only C helper decodes them with **libpng 1.6.59** into unpremultiplied
  RGBA8, stripping the low byte of 16-bit samples without color-space conversion.
- 23 valid zlib streams are independently decoded by **zlib 1.2.12**. They cover
  stored/fixed/dynamic blocks, overlapping copies, a wrapping 32 KiB history,
  sync-flush boundaries and degenerate dynamic Huffman trees.
- 341 truncated/corrupted streams are independently rejected by zlib before they
  enter the generated corpus. Common tests also enforce the output cap.

The generator pins both oracle versions. `manifest.json` records the versions,
generator/helper hashes, each PNG/pixel hash and the generated Kotlin hash.
The PNG inputs are synthetic project-owned fixtures; no upstream image files are copied.
libpng/zlib are test-generation tools, not runtime dependencies of the terminal.

Regenerate from the repository root with a C compiler and the pinned libraries:

```sh
python3 scripts/generate-terminal-image-fixtures.py --png-prefix /opt/homebrew
```

Omit `--png-prefix` to use `pkg-config libpng`. Ordinary JVM, JS and Native tests
use the checked-in Kotlin fixtures and require neither libpng nor Python.

The implementation follows [PNG Third Edition](https://www.w3.org/TR/png-3/),
[RFC 1950](https://www.rfc-editor.org/rfc/rfc1950) and
[RFC 1951](https://www.rfc-editor.org/rfc/rfc1951). The decoded PNG is the static
default image; Kitty animation is a separate frame protocol. Ancillary color
profiles are ignored, and RGBA bytes retain straight alpha for later rendering.
Image payloads must contain exactly one zlib stream: trailing bytes and concatenated
streams are rejected, matching the pinned Ghostty's decompression behavior.

The default image limits match the pinned Ghostty's 10,000-pixel maximum dimension
and 400 MiB byte ceiling. Limits apply per input/intermediate/final buffer, not to
the whole process heap. Outer zlib uses a bounded growing buffer; PNG reads IDAT
directly without concatenation, retaining only the final RGBA buffer, two scanlines
and a 32 KiB DEFLATE window (plus small tables). Store-wide image accounting and
eviction still belong to the pending graphics storage implementation.

These tests prove decoder behavior, not original-libghostty image storage/placement
parity or visible platform graphics. Those remain separate acceptance work.
